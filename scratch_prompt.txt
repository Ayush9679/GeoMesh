1. GOAL OF THIS TASK

Implement three connected capabilities on top of the existing codebase:

Citizen role: after login, a citizen can search for an area / their parcel / their ULPIN, and load the corresponding 3D building model (down to floor level) in the viewer.
Surveyor-as-master authority: a 3D ULPIN (for a building, floor, or flat) can only ever be generated/assigned by a user with the surveyor role — this must be enforced at the backend, not just hidden in the UI — and floors within a building must each carry a genuinely unique 3D ULPIN (no silent overwrite, no cross-floor collision).
AI suspicion flagging: when a citizen-facing or surveyor-facing action touches a parcel/feature/floor/flat, an AI/heuristic check evaluates it for anomalies; if something looks suspicious, the record is immediately flagged and routed into a surveyor review queue — it must NOT silently pass through.

5.2 Suspicion rules engine (new module: backend/services/ai_flagging.py)

Implement a function evaluate_suspicion(entity_type, entity, context) -> FlagResult covering at least these checks (document each as a named rule so it's demoable/explainable in the SIH pitch — judges will ask "how does the AI decide"):

Geometric overlap — reuse check_spatial_overlap from ulpin_generator; if a new/edited feature's footprint overlaps an existing feature on a different parcel, flag it.
